## Problem

The daily draft (REQ-001 AC-001-01) needs to generate "once enough of the day has passed" without
the app being open. iOS background execution is not guaranteed — the OS can defer or skip
scheduled background tasks depending on device state, battery, and usage patterns.

## Context

macOS has no equivalent restriction (launchd can reliably schedule). iOS `BGTaskScheduler` gives
no delivery guarantee — a task might not run for a day or more if the app isn't used.

## Options considered

1. **OS-scheduled background task only** (`BGTaskScheduler` on iOS, `launchd` on macOS). Simple,
   but on iOS a draft might silently never generate for a given day if the OS defers the task.
2. **Foreground check-on-open only** — generate the draft for any day missing one, the next time
   the user opens the app. Reliable (always runs when the app is used), but violates the "quiet,
   ambient" framing if the user opens the app and has to wait for generation instead of just
   reading.
3. **Both**: background task as the primary path, foreground check-on-open as a fallback that
   silently backfills any day that never got its background run.

## Decision

Option 3 — background task primary, foreground fallback silent backfill.

## Rationale

Reviewed by `architecture-reviewer`: option 1 alone fails AC-001-01 on iOS in practice (a real
device that goes days without a background run would simply have missing entries, contradicting
the requirement's "once the day has passed" language). Option 2 alone is technically reliable but
reintroduces a wait-for-generation moment the design (`DES-001`) explicitly designed against — the
"loading state" in `DES-001` was meant for the rare case, not the common one. Option 3 keeps the
common case ambient (background) while guaranteeing AC-001-01 actually holds (fallback).

## Trade-offs

Foreground fallback adds implementation surface (need to detect and backfill missing days) that
options 1/2 alone wouldn't need.

## Consequences

`TASK-005` scope includes both the background trigger and the foreground backfill check, not just
one. `TASK-005`'s verification plan must include a scenario where the background path is assumed
to have not fired, proving the foreground fallback alone satisfies AC-001-01.
